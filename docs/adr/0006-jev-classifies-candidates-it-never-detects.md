# 0006 — Jev classifies candidates; it never detects

Discovery produces far more candidates than are worth tracking, and most are broad fields ("python", "AI") or noise. Deciding "is this a specific, nameable thing?" is a narrow typed judgement — exactly what TypeSafe's Jev (a System One model: state plus typed questions in, probabilities out, ~100 ms, $0.042 per million input tokens) is built for. It cannot write text, count, or compare dates.

We decided Jev answers two questions per candidate and nothing else: a *noul* — is this a specific product, tool, technology or named thing rather than a broad field — and a *choice* of Label. A candidate at or above the tracking confidence becomes a Watching Subject, one in the uncertain band waits in Backlog for the owner, and the rest are Archived so they are never classified again. Names come from the Source's own identifiers (a Stack Exchange tag, a "Show HN" product name, a phrase repeated across titles), never from a model.

Statistics still detect: Jev's probability is never part of the Trend Score and never moves a Subject past Watching. At most a configured number of new Candidates are routed a day — names already known never count — and the rest are proposed again if they recur. Without an API key the classifier is skipped and the day's Candidates wait in Backlog, so the app degrades instead of failing. Before trusting the tracking threshold, measure Jev against about a hundred hand-labelled candidates. Amends the "a model may only group and name Subjects" rule.
